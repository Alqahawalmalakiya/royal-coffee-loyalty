# دليل النشر — بطاقة الولاء

> اقرأ هذا الدليل قبل النشر. هذه **نسخة مستقلة تمامًا** عن WebFrame. لا تستخدم مشروع WebFrame ولا أي بيانات اعتماد له.

## المتطلبات الخارجية التي نحتاجها عند وصولك لهذه المرحلة

1. حساب Supabase **آخر** ومشروع **جديد فارغ** على الخطة Free، توافق أنت على إنشائه بنفسك أو تمنح صلاحية إنشائه صراحةً. لا تستعمل قاعدة مشروع موجود.
2. حساب Cloudflare يمكنه إنشاء مشروع Pages جديد وWorker جديد، بدون إضافة وسيلة دفع أو شراء نطاق.
3. بريد إداري صالح، يمكن استخدامه لحساب الإدارة ولـ `VAPID_SUBJECT` (`mailto:you@example.com`). بريد العميل ليس مطلوبًا.
4. متصفح هاتف حقيقي لاختبار الإشعار (على iPhone يلزم iOS 16.4+، وتثبيت PWA من الشاشة الرئيسية، ثم منح الإذن).

## 1) إنشاء مشروع Supabase جديد (لا تلمس WebFrame)

- افتح [Supabase](https://supabase.com/dashboard) بالحساب الذي تريد تخصيصه للولاء.
- أنشئ مشروعًا مجانيًا جديدًا مستقلاً، بعد التأكد أن السعر 0. لا تستخدم مستضيف WebFrame أو مشروعه.
- من SQL Editor على **المشروع الجديد فقط** شغّل الملفات بالترتيب:
  - `db/001_initial.sql`
  - `db/002_skip_jobs.sql`
- إذا ظهرت مشكلة هجرة، توقف وسجّل الخطأ قبل إعادة التشغيل؛ `001_initial.sql` ينشئ مجموعة الجداول في معاملة واحدة، والتكرار قد يتسبب في تعارض أسماء.
- أنشئ مستخدم الإدارة من `Authentication → Users → Add user` باستخدام بريد الإدارة وكلمة مرور قوية، وأكد الحساب من لوحة التحكم. لا تعتمد على خدمة الإيميلات الافتراضية لإرسال الرسائل.
- انسخ UUID الخاص بالمستخدم. في SQL Editor لمشروع الولاء الجديد نفّذ مع تغيير `ADMIN_UUID_HERE`:

```sql
insert into public.staff_roles (user_id, business_id, role)
select 'ADMIN_UUID_HERE'::uuid, id, 'admin'
from public.businesses where slug = 'default';
```

- تحقّق من النتيجة عبر SQL Editor:

```sql
select role, active from public.staff_roles where user_id = 'ADMIN_UUID_HERE'::uuid;
```

- من `Project Settings / API Keys` انسخ **Project URL** و**publishable key** (لواجهة العميل). لا تستخدم `service_role` مطلقًا في `web/config.js`.
- احصل على `service_role` **السرّي** لربط Worker فقط؛ لا تنشره ولا ترسله عبر الشات؛ ضعه في صفحة Secrets في Cloudflare.

## 2) مفاتيح Web Push

شغّل على جهاز به Node 20 أو أحدث، من جذر المشروع:

```bash
node scripts/generate-vapid.mjs
```

يظهر سطران:
- `VAPID_PUBLIC_KEY` انسخ قيمته فقط إلى `web/config.js`.
- `VAPID_PRIVATE_JWK` لا تضعها في ملفات الويب ولا تشاركها. ضعها في Cloudflare Worker Secret باسم `VAPID_PRIVATE_JWK`.

احفظ نسخة آمنة من المفتاح الخاص لدى إدارة النشاط؛ تغييره لاحقًا يتطلب إعادة اشتراك الأجهزة بالإشعارات.

## 3) إنشاء Cloudflare Worker **جديد** للإشعارات والتفعيل

في مجلد `worker/` توجد:
- `index.js`: واجهات التفعيل والاستعادة، والوظيفة الدورية.
- `webpush.js`: تشفير Web Push والتوقيع.
- `wrangler.toml`: Cron كل 5 دقائق (بالتوقيت UTC؛ تُفحص الساعة المحلية في قاعدة البيانات).

حدّث المتغيرات العامة في `worker/wrangler.toml`:

- `SUPABASE_URL`: رابط المشروع الجديد.
- `ALLOWED_ORIGIN`: دومين تطبيق Pages الجديد **بالضبط**، مثل `https://loyalty-cards.pages.dev`.
- `VAPID_SUBJECT`: بريد إداري بصيغة `mailto:...`.

انشر Worker من الجهاز عبر Wrangler، أو عبر لوحة Cloudflare بإضافة ملفات Worker والـ Cron يدويًا. إذا توفر npm:

```bash
cd worker
npx wrangler login
npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY
npx wrangler secret put VAPID_PRIVATE_JWK
npx wrangler deploy
```

**مهم:** يجب نشر Worker بعدما تكون `ALLOWED_ORIGIN` معروفة؛ يمكن إنشاء Pages أولًا ثم إكمال إعداد Worker ورفع Pages مرة ثانية. تأكد أن Cloudflare لم يطلب ترقية خطة.

Cron: `*/5 * * * *`. هذا لا يرسل للجميع كل 5 دقائق افتراضيًا؛ بل يفحص طابور الإشعارات. التذكير التسويقي مرة أسبوعيًا يوم الخميس 17:00 بتوقيت الرياض. وضع اختبار «كل 5 دقائق» يتم تشغيله يدويًا من لوحة الإدارة لمدة 30 دقيقة فقط.

## 4) نشر واجهة Cloudflare Pages مستقلة

1. انسخ `web/config.example.js` إلى `web/config.js` أو عدّل `web/config.js` الموجود.
2. ضع فيه `SUPABASE_URL` و `SUPABASE_PUBLISHABLE_KEY` و `WORKER_URL` (دومين workers.dev) و `VAPID_PUBLIC_KEY`. اسم النشاط اختياري.
3. لا تضع أي مفتاح سرّي في `web/` أو GitHub أو ملف zip الخاص بـ Pages.
4. افتح `Cloudflare Dashboard → Workers & Pages → Create → Pages → Direct Upload`.
5. أنشئ **مشروع Pages جديدًا** وارفع مجلد `web` (أو أرشيف ZIP يحتوي ملفات `index.html` في الجذر، بدون مجلد `web` خارجي).
6. تأكد أن موقع Pages على HTTPS وأن الملفات `manifest.webmanifest`, `service-worker.js`, `config.js` تُحمّل بنجاح.
7. Cloudflare Pages عادة يعيد مسارات SPA إلى `index.html` عند عدم توفير `404.html`؛ تأكد عمليًا أن `/activate` و `/recover` يعرضان التطبيق مباشرة.
8. تأكد من إعداد Origin Worker الصحيح، وأن `/health` يعطي JSON يحتوي `ok:true`.

## 5) QR التسجيل العام

بعد معرفة رابط موقع Pages الحقيقي:

```bash
python scripts/make-public-qr.py https://YOUR_NEW_PAGES.pages.dev
```

ينتج ملف `public-registration-qr.png` ويمكن طباعته. **العميل لا يسجّل نفسه من هذا QR** في النسخة البسيطة؛ أنت تضيفه في لوحة الإدارة ثم ترسل رابط تفعيل خاص به. رمز العميل داخل بطاقته يعرض رقم العضوية فقط ولا يفتح جلسة ولا يسمح بالاستبدال.

## 6) اختبار أول عميل

1. افتح موقع Pages واضغط «دخول العميل / الإدارة» ثم تبويب الإدارة وسجّل ببريدك.
2. أضف عميلًا؛ انسخ رابط التفعيل الخاص الذي يظهر مرة واحدة.
3. على هاتف العميل، افتح الرابط وأنشئ كلمة مرور (12 حرفًا أو أكثر) ووافق على سياسة الخصوصية.
4. أضف التطبيق للشاشة الرئيسية. على iPhone افتح Safari → مشاركة → إضافة إلى الشاشة الرئيسية.
5. افتح البطاقة وتأكد أن رصيد العميل صفر وأن رمز QR صالح.
6. من الإدارة، أضف مناسبة واحدة بالتاريخ → ينبغي ظهور 1/6.
7. أضف خمس مناسبات أخرى بتواريخ/أوصاف متميزة → ينبغي أن تظهر هدية «قهوتان مجانًا» واحدة بالضبط.
8. جرّب استبدال الهدية مرة واحدة. المحاولة الثانية يجب أن تُرفض.
9. من بطاقة العميل → الإعدادات: فعّل اختيار استقبال العروض، ثم امنح إذن الجهاز بعد التثبيت.
10. من لوحة الإدارة → الإشعارات، جرّب «تجربة ٥ دقائق» لمدة 30 دقيقة فقط. أوقفها بعد التحقق.
11. راجع حالة الطلبات المقبولة أو الفاشلة لدى خدمة Push. قبول الخدمة لا يعني ضمان وصول إشعار للشاشة.

## 7) قبل الإطلاق العام

- جرّب تسجيل الدخول وإعادة تفعيل كلمة مرور عميل بموافقة الإدارة.
- راجع سياسة الخصوصية واسم المنشأة والبيانات والتزامات PDPL ونقل البيانات.
- راجع Security Advisor في Supabase، واختبر RLS باستخدام حسابين مستقلين، ولا تعتبر اختبارات SQL المحلية بديلًا عن ذلك.
- جرّب push على iPhone وAndroid حقيقيين، فالنتائج تختلف حسب المتصفح والنظام.
- اختبر إن كان Worker لا يتجاوز حدود CPU أو subrequests بالرصيد الفعلي.
- ضع خطة نسخ احتياطي منتظمة؛ Supabase Free لا يقدم نسخًا احتياطيًا تلقائيًا مضمونا مثل الخطط المدفوعة.

## 8) مشاكل شائعة

- **"Server is not configured"**: Worker secrets أو المتغيرات العامة غير مضبوطة.
- **"المشروع جاهز للربط"**: `web/config.js` ما زال فارغًا.
- **خطأ التفعيل**: تحقق أن رابط العميل لم تنته مدته أو يُستخدم سابقًا، وأن `service_role` لخدمة الولاء الجديدة وليس WebFrame.
- **خطأ عند الدخول**: تأكد أن حساب الإدارة موجود في `staff_roles` وأن عميلك فعّل الرابط الخاص به.
- **لا تظهر إشعارات iPhone**: يجب تثبيت PWA على الشاشة الرئيسية وفتح التطبيق من الأيقونة، ثم منح الإذن في تفاعل مباشر.
- **لا تصل العروض**: يلزم `marketing_opt_in` مفعّل، واشتراك جهاز نشط، ومهمة Cron منشورة، وألا يكون مشروع Supabase متوقفًا.
